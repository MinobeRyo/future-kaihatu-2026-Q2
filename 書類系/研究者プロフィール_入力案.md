## 研究概要（日本語20〜2,000字 / 任意・公開）

私は長年ギターを弾いてきて、最近になって電子ピアノも始めました。ただ、その弾き方はほとんど感覚に頼ったもので、「なんとなくこの響きが好き」「ここでこう動かすと気持ちいい」という体の記憶だけで演奏してきました。そこから音楽理論をきちんと学ぼうとしたときに、二つの壁にぶつかりました。ひとつは、理論の説明と自分の感覚とのあいだにズレがあること。もうひとつは、自分がやりたい響きや動きを、言葉としてどう指せばよいのか分からないことです。感覚は先にあるのに、それに名前がついていないという状態でした。

ここから生まれたのが、「好き」という感覚をそのまま勉強に落とし込めるようにしたい、という動機です。音楽をやっているかどうかに関わらず、誰にでも「この曲のこのフレーズが好き」「このサビの響きがたまらない」という瞬間があります。理論の知識はゼロでも、その感覚だけはすでに全員が持っている。ならば、そこを入口にして学び始められるはずだ、と考えました。これを形にしているのが、Webアプリ「積み音（つみね）」です。

積み音がめざすのは、**音楽理論をこれから学ぶ初心者に向けた、学習サポートと作曲を1つにしたアプリ**です。理論書とDTMソフトのあいだには大きな段差があり、初心者は「理論は分かったつもりだが、では何を作ればいいのか」で止まってしまいます。学ぶ場所と作る場所を同じアプリの中に置くことで、この段差をなくすことを狙っています。

何が「好き」の入口になるかは人によって違うため、アプリには6つのモードを用意し、それぞれ別のアプローチから理解に近づけるようにしています。半音・3度・コードの積み上がりを7ステップで体験する**入門モード**、1つのコードにテンションを足しながら「音の積み木」として響きの変化を確かめる**練習モード**、コードを個別に読んで学ぶ**解説モード**、五度圏で理論を可視化する**魔法陣モード**、2つの進行を同じキー・テンポで並べて切り替える**聴き比べモード**、そしてピアノロール上でコード・メロディ・ベースの3トラックを組み立てる**作曲モード**です。

これらは順番に進む階段ではありません。どのモードから入っても、また何度行き来しても構わない設計にしています。読んで分かる人もいれば、聴き比べて初めて腑に落ちる人も、図で見て掴む人もいます。重要なのは、どの入口から入っても最終的に「作る」につながることで、聴き比べで気に入った進行はそのまま作曲モードへ持ち込めますし、逆に作った進行を解説や魔法陣で確かめ直すこともできます。

設計原則は一貫して「音の後に言葉」です。テンションを足した瞬間に増えた音だけを別色で光らせる、和音を下から1音ずつ積んで鳴らす、操作した内容をその場で短い日本語の解説として返す。先に響きを体験させ、そのあとで「いま起きたことにはこういう名前がついている」と示す順序を守ることで、感覚のほうから理論の言葉へ手が届くようにしています。作曲モードでは、初心者が手を止めないための支援機能として、次に置くコードの候補を「自然につなぐ／盛り上げる／締める／意外性」の4つの役割つきで提案する機能、メロディの次の音を提案する機能、コード進行から旋律を自動生成する機能を実装しました。さらに、自分が組んだ進行を楽曲データベースと照合し「その進行は小室進行の変形です」と返す逆引き機能を入れ、作った結果からも理論を学び直せるようにしています。

これらを支えているのが、コード進行をキーに依存しない度数の並び（例: IV→V→iii→vi）として持つ、という設計判断です。理論そのものをデータ構造として定義したことで、移調・度数表示・楽曲照合・コード提案をすべて同じ定義から導けるようになりました。

まだ個人開発の途上で、音源からのコード進行推定やハモリ機能は今後の課題です。それでも「自分が欲しかった学び方」を形にし、理論用語を知らない人が音楽理論に触れ、そのまま作曲まで踏み出せる入口をつくることを目指しています。

# 【重要】動機の軸 ― ここをずらさない

今後この文章を書き直すとき、以下の軸は必ず維持すること。過去に何度かずれたので明記しておく。

## 軸となる動機

**「好き」という感覚を、そのまま勉強に落とし込みたい。**

- 音楽をやっていてもいなくても、誰にでも「この曲のこのフレーズが好き」「このサビの響きがたまらない」という瞬間がある
- 理論の知識はゼロでも、**その感覚だけは全員がすでに持っている**
- ならば、そこを入口にして学び始められるはず ← これがアプリの根本思想

## 対象ユーザー

**音楽理論をこれから学ぶ初心者。** 経験者向けではない。

- 開発者本人（ギター歴長い／電子ピアノを最近開始／感覚頼りで弾いてきた）の経験は、
  あくまで**動機が生まれた背景**として書く。アプリの対象ではない
- 本人の経験から出てきた気づき: 理論の説明と自分の感覚とのズレ／
  やりたい響きを言葉でどう指せばいいか分からない

## やりがちなズレ（禁止）

| ✕ 書いてはいけない | ○ 正しい |
|---|---|
| 「教則本を読んでも腑に落ちない初心者だった」 | 感覚で弾けてはいた。理論の言葉と結びつかなかった |
| 「すでにある感覚と理論の言葉を結びつけるアプリ」（＝経験者向けに読める） | 初心者向けの学習サポート＆作曲アプリ |
| 技術（度数正規化・逆引き検索）をタイトルや主語に置く | 主語は「学習サポート＋作曲」。技術は裏方として最後に触れる |
| 「前半5モードが学ぶ、最後が作る」「順に進む」 | 6モードは**並列のアプローチ**。順番は関係ない |
| 「マルコフ連鎖」「◯%の曲がこう進む」 | 実装はルールベース（下の差分メモ参照） |

## 6モードの位置づけ

**順番に進む階段ではない。** 何が「好き」の入口になるかは人それぞれなので、
入門／練習／解説／魔法陣／聴き比べ／作曲を**並列のアプローチ**として用意している。

- 読んで分かる人、聴き比べて腑に落ちる人、図で掴む人、それぞれ違う
- どこから入ってもよく、何度行き来してもよい
- 共通しているのは、**どの入口から入っても最終的に「作る」につながる**こと
- 聴き比べ→作曲、作曲→解説・魔法陣で確認、と双方向に行き来できる

## 企画書に無い、実装で増えた要素（アピール材料）

- **入門モード（`tutorial.html`）**: 半音→3度→コードの積み上げを7ステップで体験。企画書段階では存在しなかった新ページ
- **メロディ／ベースの「次の音」提案**（`suggest.js`）: コード構成音・直前の音・キーから、役割つきで候補を提示。ドレミボタンの「合う/合わない」2値表示からの発展
- **おまかせメロディ生成**（`melodyGen.js`）: 「くりかえし／起承転結／なめらか／はずむ」の4スタイル。旧実装の固定アルペジオを、乱数＋スタイル別パラメータ（音長プール・コード構成音率・休符率）に置き換え
- **曲の保存／読み込み**（`songFile.js`）: バージョン管理つきJSON。DB保存に移行しても入出力層だけ差し替えれば済む設計
- **表記の切替**: ♯/♭表記モード、コード表記スタイル、ダーク/ライトテーマを全ページ共通で localStorage 管理
- **テスト**: `tests/selftest.mjs`（依存なし）、`tests/composeSmoke.mjs`（jsdom）。`core/` と `data/` を DOM 非依存に保つ設計ルールとセット
- **プリセット5種目「お試しコード」**: ツーファイブワン→転調を含む7コード進行、原曲キー（G♭）とベースライン指定つき
