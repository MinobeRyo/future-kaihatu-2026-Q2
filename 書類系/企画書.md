# 積み音（つみね）発展企画書

アプリ名: **積み音（つみね）** / TUMINE
由来: コードは音を積み上げてできているという体感（練習モードの「音の積み木」）をそのまま名前にした。「音(ね)」は音色・響きそのものを指す訓読み。初出では必ず読みを併記する。

作成日: 2026年7月10日
作成者: ryom（データサイエンス学部2年）
開発体制: 個人開発
提出目的: コンテスト・発表会

## 0. 動機 ― この企画の軸（2026年7月31日追記）

**この節がすべての判断の基準になる。以下の軸から外れる書き方・機能追加はしない。**

### 軸となる動機

**「好き」という感覚を、そのまま勉強に落とし込みたい。**

音楽をやっているかどうかに関わらず、誰にでも「この曲のこのフレーズが好き」「このサビの響きがたまらない」という瞬間がある。理論の知識はゼロでも、**その感覚だけはすでに全員が持っている**。ならば、そこを入口にして学び始められるはずだ——というのが、このアプリの根本思想である。

### 動機が生まれた背景（開発者本人の経験）

開発者は長年ギターを弾いてきて、最近になって電子ピアノも始めた。ただしその演奏はほとんど感覚に頼ったもので、「なんとなくこの響きが好き」「ここでこう動かすと気持ちいい」という体の記憶だけで弾いてきた。そこから音楽理論をきちんと学ぼうとしたときに、二つの壁にぶつかった。

1. 理論の説明と、自分の感覚とのあいだにズレがある
2. 自分がやりたい響きや動きを、言葉としてどう指せばよいのか分からない

感覚は先にあるのに、それに名前がついていない。この経験が動機の出発点である。

### 対象ユーザー

**音楽理論をこれから学ぶ初心者。** 経験者向けではない。

上記の「開発者本人の経験」は、あくまで**動機が生まれた背景**として扱う。アプリが向き合う相手は初心者であり、本人と同じ経歴の人を想定しているわけではない。

### 6モードの位置づけ

**順番に進む階段ではない。** 何が「好き」の入口になるかは人によって違うため、入門／練習／解説／魔法陣／聴き比べ／作曲は**並列のアプローチ**として用意する。

- 読んで分かる人、聴き比べて初めて腑に落ちる人、図で見て掴む人、それぞれ違う
- どのモードから入ってもよく、何度行き来してもよい
- 共通しているのは、**どの入口から入っても最終的に「作る」につながる**こと
- 聴き比べ→作曲、作曲→解説・魔法陣で確認、と双方向に行き来できるようにする

## 1. 背景・現状

すでに「音楽コード勉強アプリ」として、以下4つのページからなるWebアプリを開発済みである（Vanilla JS + Web Audio API + Soundfont-player）。

| ページ | 機能概要 |
|---|---|
| `main.html`（練習モード） | 88鍵ピアノで実際にコードを演奏し、ボイシングや音色の違いを体験できる |
| `compose.html`（作曲モード） | コード進行・メロディ・ベースをタイムラインに配置して作曲する |
| `learn.html`（コード解説モード） | 単音・メジャー・マイナー・セブンスなどのコードを個別に学べる |
| `魔法陣.html`（魔法陣表示） | 五度圏・ダイアトニックスケール・コード三角形を視覚的に表示する |

音楽理論を「聴いて」「弾いて」「見て」学べる点が既存アプリの強みである。一方で、開発者自身の課題認識として次の点がある。

- 作曲モードのUIが直感的でなく、初心者が「何をどう配置すればよいか」を理解しにくい。シンプルに使いにくい。
- コード進行を学ぶ手段が理論知識ベースにとどまり、既存曲を題材にした実践的な学習ができない
- 使える音色（楽器）が限定的で、音の違いを比較する体験が弱い
- コードにテンション（9th, 11th, 13thなど）を加えたり、キーを移調する操作が用意されていない

## 2. 企画の目的

既存アプリを土台に、「聴く・弾く・見る」に加えて「**既存曲から学ぶ**」「**自分で音を作り替える**」体験を追加し、音楽理論初心者でも直感的にコードとコード進行を理解できる学習アプリへと発展させる。

「自分が欲しいアプリを自分で作る」という視点を企画の軸に据える（動機の詳細は **0章** を参照）。テンションを足したときに何が起きているのか、コードを重ねた（ハモった）ときになぜその響きになるのかを、理屈より先に耳と目と短い解説で理解できることを最優先の体験目標とする。「好き」という感覚を入口にして、そこに理論の言葉を後から結びつける——この順序を守ることが、全機能に共通する設計原則である。

コンテスト・発表会では、以下をアピールポイントとする。

- 既存曲の音源からコード進行を解析し、学習教材として自動生成する独自性
- よくあるコード進行（王道進行、カノン進行など）をワンクリックで試聴・アレンジできる実用性
- テンション追加・移調をリアルタイムに操作できる音楽理論の可視化

## 3. 発展機能案

開発期間が1ヶ月・個人開発であることを踏まえ、実現難易度で優先順位を分けた。

### ページ構成方針（既存構成は崩さない）

設計原則は「**1ページ=1つの体感**」。既存4ページの役割は据え置き、新規追加は「進行聴き比べ」1ページのみとする。解説（③）は各ページに埋め込み、常に「音の後に言葉」の順で出す。

| ページ | 役割（据え置き） | 追加する機能 |
|---|---|---|
| main（練習） | 1つのコードを弾いて体感 | ②テンション操作・A/B試聴・複雑さメーター、③解説キャプション |
| compose（作曲） | 自由作曲に専念 | ④ピアノロール刷新、3トラック同時再生、プリセット呼び出し、逆引き検索（①-2b）、⑦おすすめコード提案、⑧自動ハモリ、⑤音色 |
| learn（解説） | 読んで学ぶ辞典 | 進行解説＋楽曲紐付けリスト（①-2a）。各所の「もっと詳しく」の飛び先 |
| 魔法陣 | 理論の可視化 | 再生連動ハイライト（進行＝五度圏上の移動を見せる） |
| **新規: 進行聴き比べ** | 進行を並べて比べて体感 | ①プリセット試聴・移調、①-3聴き比べUI、楽曲リスト表示 |

導線は「聴き比べ（インプット）→ 作曲モードで開く → 自由作曲 → 逆引き（フィードバック）」の一方向ループとし、発表デモの台本もこの流れに沿って構成する。

### 優先度A（MVPとして必ず実装）

**① コード進行プリセット＆既存楽曲リンク機能**

Jポップでよく使われる定番進行を最初から4種類搭載する（Cメジャーキーでの例）。

| 呼び名 | 度数進行 | コード例（Key=C） | 雰囲気の説明（アプリ内表示） |
|---|---|---|---|
| 王道進行 | IV → V → iii → vi | F → G → Em → Am | 切なさと爽やかさが同居する、Jポップ王道の響き |
| カノン進行 | I → V → vi → iii → IV → I → IV → V | C → G → Am → Em → F → C → F → G | 壮大で感動的な、定番バラードの響き |
| 小室進行 | vi → IV → V → I | Am → F → G → C | 90年代J-POPに多い、疾走感のある響き |
| 丸サ進行 | IVM7 → III7 → VIm7 → I7 | FM7 → E7 → Am7 → C7 | オシャレでジャジーな、都会的な響き |

※丸サ進行の度数は「Just the Two of Us進行」（IVM7 → III7 → VIm7 → I7）に修正した（旧企画書の記載は誤り）。

- 各プリセットはワンクリックで試聴でき、キー移調（トランスポーズボタン）にも対応する
- プリセットを選ぶと、④のピアノロールに自動で配置される（優先度Aの①④は同じ導線でつながる）

**①-2 既存楽曲との関連性比較（紐付け表示＋逆引き検索）**

「この進行、あの曲だ！」という気づきを学習の入口にする。理論用語より先に知っている曲で体感させる、本アプリの中核的な差別化機能。

(a) 紐付け表示: 各プリセット進行に「この進行が使われていると広く紹介されている楽曲リスト」を表示する。

| 進行 | 代表曲の例（アプリ内に曲名・アーティスト名のみ掲載） |
|---|---|
| 王道進行 | 残酷な天使のテーゼ / 愛をこめて花束を / 夜に駆ける（サビ） |
| カノン進行 | チェリー（スピッツ） / さくら(独唱) / キセキ |
| 小室進行 | Get Wild / CAN YOU CELEBRATE? / Lemon（サビ） |
| 丸サ進行 | 丸の内サディスティック / Just the Two of Us / 死ぬのがいいわ |

- 曲名・アーティスト名・コード進行（事実情報）の掲載のみで、音源・歌詞・楽譜は一切使わないため著作権リスクなし
- 楽曲データは `songs.js` に度数ベース（キー非依存）で20〜30曲を手動収録する。収録前に耳とコード譜サイトで照合・検証する

(b) 逆引き検索（楽曲マッチング）: ユーザーが作曲モードで組んだコード進行を度数解析し、楽曲DBと照合して「あなたの進行は『Lemon』と同じ小室進行です」のようにその場で返す。

- 進行をキー非依存の度数列に正規化 → DB内の進行パターンと部分一致・巡回一致で照合する
- 完全一致だけでなく「王道進行の変形です（3つ目のコードが違う）」のような近似判定も表示し、学びにつなげる
- テンションの有無は無視してトライアド単位で照合する（初心者向けの割り切り）

**①-3 進行聴き比べページ（新規ページ）**

「作る前のインプット」を担う専用ページ。自由作曲（compose）と役割を分けることで、両者のUIをシンプルに保つ。

- 2つの進行（例: 王道 vs 小室）を**同じキー・同じBPM**に揃えて縦に並べ、ループ再生中にワンタップで切り替えられるようにする。テンポを止めずに響きだけが変わるのが体感の肝
- 2つの進行で違うコードだけを色でハイライトし、「どこが違うから印象が変わるのか」を目でも追えるようにする
- 各進行に代表曲名（①-2a）を添えて表示する
- 「この進行を作曲モードで開く」ボタンでcomposeへ雛形として送る
- 余裕があれば同ページに聴き比べクイズ（ランダム再生した進行を当てるミニゲーム。発表会で来場者参加型にできる）を追加する

**② テンションコード操作機能（初心者向けの「響きの変化」を体感できる設計）**

初心者が理屈より先に「耳と目」でテンションの効果を理解できることを重視する。
- 選択中のコードに対し、9th / 11th / 13th / add9 / sus4 などのテンションをトグルボタンで追加・削除できる
- ボタンには理論用語だけでなく、「浮遊感が出る（9th）」「和風・浮遊感（11th）」のような一言解説を添え、初心者でも押した結果をイメージできるようにする
- テンションを追加すると、鍵盤・ピアノロール上で追加された音だけ色を変えてハイライトし、「どの音が増えたか」を視覚的に示す
- 「元のコード」と「テンション追加後」をワンクリックで聴き比べられるA/B試聴ボタンを用意する
- 追加したテンションの数に応じて「響きの複雑さメーター」を表示し、シンプル⇔複雑の変化を直感的に把握できるようにする
さらに、「説明を読ませる前に差分を聴かせて見せる」原則に基づく体感設計を加える。

- **1音ずつ積む再生**: C→E→G→D5 と下から順にゆっくり鳴らしてから全音を同時に鳴らす。テンション音だけ鍵盤上で別色に光らせ、「どの音が増えて響きがどう変わったか」を耳と目で同時に伝える
- **ループ中のA/Bトグル**: コードをループ再生しながらテンションボタンをON/OFFできるようにする。テンポを止めずに響きだけが変わる（①-3聴き比べと同じ原則のコード版）
- **「同じ音なのに」デモ**: 9thの正体は「レ」。CコードにD4（ルートのすぐ隣）を足すと濁るのに、D5（1オクターブ上）だと洒落た響きになる——同じ音でも置く高さで響きが変わることをボタン2つで聴かせる。テンション理解の核心を1操作で伝える発表向きデモ
- **テンションの色を全ページで統一**（9th=水色、11th=紫 など）: 鍵盤・ピアノロール・魔法陣で同じ音が同じ色になり、ページを跨いで直感が繋がる
- 実装は新アーキテクチャの `musicTheory.js`（テンション定義・追加音ハイライト計算は実装済み）を全ページから共有する

**③ 初心者向けリアルタイム解説機能**
開発者自身が初心者であるという原点に立ち、「操作した結果、理論的に何が起きたか」をその場で言葉にして返す機能を追加する。

- テンションを追加した瞬間、コードを重ねてハモリ（コード演奏）を鳴らした瞬間などに、画面の一角に短い解説キャプションを表示する
  - 例:「9thを足すと、少しおしゃれで浮遊感のある響きになります」
  - 例:「Am → F は、明るい響きから少し切ない響きへの定番の移り変わりです」
- 解説文は `learn.html` の解説データを流用・拡張し、コード計算ロジック（`chordCalculator.js`）の出力に対応させる形で管理する
- 「もっと詳しく」をクリックすると `learn.html` の該当コード解説へ遷移できるようにし、練習モード・作曲モードと解説モードを回遊できる導線にする

**④ 作曲モードのUI/UX刷新（右側プレビューのピアノロール化）**

左側の「コード選択パネル」（基礎音・調号・コードタイプ・オクターブ・長さ・選択中プレビュー・追加ボタン）は既存のボタン構成をそのまま維持する。使い慣れた操作フローを崩さず、変更は右側のタイムラインエリアに集中させる。

- 現状、右側は「メロディ／コード進行／ベース」の3トラックがシンプルな枠として並んでいるだけで、視覚的な情報量が少ない
- これを、DAW（作曲ソフト）でよく使われる「ピアノロール」形式の大きなプレビューに刷新する
  - 縦軸に音高、横軸に時間（カウント）を取ったグリッド上に、左パネルで「追加」した音・コードが色付きのブロックとして表示される
  - 左パネルでコード（例:「Cマイナー」）を選んで「タイムラインに追加」すると、該当する構成音がグリッド上に自動でブロック化されて配置される
  - ブロックはクリック・ドラッグで位置や長さを個別に調整でき、自動配置後も自由に編集できる
  - グリッド上部に、現在配置されているコード進行（例:「Cm7 → F → G」）をリアルタイムで表示する
  - メロディ・ベースは、ピアノロールの下に小さなサブトラックとして併記し、全体を見渡しやすくする
- 全体としてブロックの角丸・配色・余白を整理し、既存の枠線ベースの表示より視覚的に洗練されたプレビューにする

この方針により、「左のボタンで演奏の土台を作り、右の大きなピアノロールで全体を見ながら微調整する」という、既存の操作性を崩さない自然な作曲フローを実現する。既存の `composeState.js`（タイムライン状態管理）・`composeUI.js`（描画）のロジックはそのまま活かし、描画部分をピアノロール形式に置き換える形で実装する。

**⑦ 次のおすすめコード提案機能（作曲アシスト）**

作曲中、直前のコードから「次に来るコード」の候補を3択で提案する。データサイエンス学部の学びと直結する、本アプリの発表上の目玉機能。

- 楽曲DB（①-2）の進行を度数列に正規化し、コード間の遷移確率をマルコフ連鎖として集計する（逆引き用の度数解析ロジックをそのまま流用できる）
- 作曲中に候補を3つ表示し、それぞれに「定番（68%の曲がこう進む）」「おしゃれ」「意外性」のような性格ラベルを付ける
- **候補にカーソルを乗せると試聴できる**ようにし、「聴いてから選ぶ」体感原則と一貫させる。クリックでそのままタイムラインに追加
- 遷移データは自作の楽曲DBを基本とし、McGill Billboardコーパスなど研究用のコード注釈データセットでの拡充を検討する（合法・出典明記）
- 発表では「J-POP進行データから学習した推薦」としてアルゴリズム（度数正規化→遷移確率→ランキング）を図解する

### 優先度B（実装できれば大きな差別化になる）

**⑤ 楽器音源の追加**
- Soundfont-playerが対応する音色（ギター、ベース、ストリングスなど）を選択肢に追加
- 新アーキテクチャの `audioEngine.js` の `loadInstrument()` を拡張するだけで対応可能なため、実装コストは比較的低い

**⑤-2 体感ドリブンの追加進化案（優先度B、コンセプト:「理論じゃなくて体感」）**

初心者向け・体感重視という軸をさらに強めるための追加案。①〜④完成後に着手する。

- **度数モード（移調の体感）**: コード名表示を「F → G → Em」と「IV → V → iii」で切り替えられるようにする。キーを変えて再生しても度数表示が変わらない（＝響きの関係は同じ）ことを耳で確かめられ、「進行はキーに依存しない」という理論の核心を操作だけで体感できる。逆引き機能（①-2）の度数解析ロジックをそのまま流用できるため実装コストが低い
- **感情タグから探す**: 「切ない」「爽やか」「おしゃれ」「疾走感」のタグから進行・楽曲を逆引きする。理論用語を一切知らなくても入口に立てる
- **五度圏連動アニメーション**: 進行再生中に、既存の魔法陣（五度圏）上で現在のルート音がリアルタイムにハイライト移動する。「コード進行＝円の上の移動」として視覚的に体感できる（既存 `MusicMagicCircle.js` の描画ロジックを流用）
- **3トラック同時再生**: 旧アプリはメロディ・コード・ベースのうち選択中の1トラックしか再生できなかった。新実装では3トラック同時再生を標準とし、「ベースを足すと急に曲っぽくなる」体感を提供する
- **PCキーボード演奏**: A〜Lキーなどを鍵盤に割り当て、マウスより気軽に音を出せるようにする

**⑧ ハモリ体感機能**

「ハモると気持ちいいのはなぜか」を、理屈より先に耳と目で理解させる。

- **自動ハモリボタン（compose）**: メロディトラックに「3度下ハモを付ける」トグルを追加。自分のメロディがワンタップでデュエットになる。自由作曲との相性が良く、体験のインパクトが大きい
- **間隔の聴き比べ実験室**: 同じ短いメロディを「2度（ぶつかる）/3度（きれい）/5度（力強い）/6度（やわらかい）」でハモらせて切り替える。ハモリ理論の実体＝音程の性格そのものを体感させる
- **なぜ3度が合うかの種明かし**: ハモリ音が実はコード構成音に乗っていることを、鍵盤上でコードの色とハモリ音の色が重なる形で見せる（②の色統一ルールと同じ仕組みで実装できる）
- 配置は、自動ハモリ＝compose、間隔の実験室＝learnの進行セクション（またはmainのタブ）とする

### 優先度C（発展・将来構想として企画書に明記、実装は時間次第）

**⑥ 音源からのコード進行解析機能**

技術検証の結果、1ヶ月・個人開発では次の着地点で実装することを企画として確定する。

- **入力**: 外部URL（YouTube等）からの直接解析は著作権上のリスクがあるため対象外とし、ユーザー自身が権利を持つ音声ファイル（mp3/wav）のアップロードのみを対象とする
- **解析方式**: Web Audio APIの `AnalyserNode` でFFTを行い、クロマ特徴量（12音のエネルギー分布）を一定間隔で抽出し、あらかじめ用意したコードテンプレート（メジャー/マイナートライアド中心）との類似度で最も近いコードを推定する簡易アルゴリズムを実装する
  - 音楽理論計算に強い軽量ライブラリ（Tonal.jsなど）をコード名変換の補助に利用することを検討する
- **対応範囲**: 精度が不安定になりやすい7th以上のテンションコードや転回形までは対象とせず、メジャー/マイナーの基本トライアド単位での推定にとどめる（MVPとして「大枠のコード進行がなんとなく見える」ことをゴールとする）
- **出力・活用方法**: 解析結果を④のピアノロールにそのまま読み込み、「聴いた曲のコード進行を自分の作曲モードで確認・アレンジできる」導線につなげる
- **発表会での見せ方**: 精度に限界がある前提を明示した上で、「既存曲の構造を自動で可視化するプロトタイプ」として、簡単な曲での解析デモを行う

## 5. 技術方針（完全新規リビルド）

旧アプリはバグが多いため、**ファイルは全て新規作成**とし、旧コードは「ロジックの参考資料」としてのみ使う。旧アプリの調査で判明した構造的問題は以下の通りで、これらが新設計の根拠である。

### 旧アプリの構造的問題（調査結果）

| 問題 | 内容 |
|---|---|
| ロジックの三重実装 | コード計算が `chordCalculator.js` / `composeAudio.js` / `learnMain.js` の3箇所に別々に実装されており、修正漏れ・挙動のズレの温床になっている |
| 停止ボタンが効かない | `stopPlayback()` は `isPlaying` フラグを変えるだけで、`playTimeline()` 内の `setTimeout` 連鎖がフラグを確認しないため、停止後も再生が続く |
| 1トラックしか再生できない | `playTimeline()` が `activeTrack` のみ再生する設計で、メロディ・コード・ベースを重ねて聴けない |
| setTimeoutベースの再生 | タイマー精度に依存しテンポが揺れる。Web Audio APIの `currentTime` ベースのスケジューリングに置き換えるべき |
| デバッグコードの残留 | 全ファイルに `console.log` が大量に残り、可読性と保守性を下げている |

### 新アーキテクチャ

「音楽理論の計算」「音を鳴らす」「データ」「画面」を完全に分離し、全ページが同じエンジンを共有する。

```
app/
├── index.html / compose.html / learn.html …（画面）
├── js/
│   ├── core/
│   │   ├── musicTheory.js   # 理論エンジン（音名⇔MIDI変換、コード計算、テンション、度数解析、移調）※全ページ共通・唯一の実装
│   │   └── audioEngine.js   # 再生エンジン（楽器ロード、AudioContext時刻ベースの進行再生、確実に効く停止、3トラック同時再生）
│   ├── data/
│   │   ├── progressions.js  # プリセット進行（度数ベース定義）＋雰囲気解説
│   │   ├── songs.js         # 既存楽曲DB（度数ベース・キー非依存）＋逆引きマッチング
│   │   └── captions.js      # 初心者向けリアルタイム解説の文言データ
│   └── pages/               # 各ページ固有のUIロジック（core/dataを呼ぶだけの薄い層）
└── css/
```

- 旧 `chordCalculator.js` / `config.js` の計算ロジック・定数は `musicTheory.js` に統合移植する（関数の考え方は流用、コードは書き直し）
- 進行・楽曲・解説文はすべて**度数ベースのデータ**として定義し、移調・逆引き・度数モードを同じ仕組みで実現する
- 音源解析（優先度C）は独立モジュールとして切り出し、コア部分の安定性に影響させない
